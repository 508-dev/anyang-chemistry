# Android Release & Publishing Guide

This document covers how to build, test, and publish releases of Anyang Chemistry to GitHub, Google Play, and F-Droid.

## Release Process Overview

The release workflow uses [release-please](https://github.com/googleapis/release-please) to automate semantic versioning and GitHub Actions to build and publish:

1. **Submit changes** to the `main` branch via PR as usual
2. **Merge to main** → release-please automatically opens a "chore(main): release X.Y.Z" PR
3. **Review & merge the release PR** → workflow tags vX.Y.Z and creates a GitHub Release
4. **GitHub Actions** automatically builds the signed APK/AAB and publishes to configured stores

## Version Management

Version numbers live in a single source of truth:

- **`version.txt`**: The canonical version (e.g., `0.1.0`)
- **`CHANGELOG.md`**: Auto-generated by release-please; describes each version
- **`apps/web/android/app/build.gradle`**: Derived from version.txt via `scripts/sync-version.sh`
  - `versionCode`: Computed as `major * 1000000 + minor * 1000 + patch` (e.g., 0.1.0 → 1000)
  - `versionName`: Directly from version.txt

**Do not manually edit version numbers in build.gradle** — they're regenerated from version.txt.

## Scripts

### `scripts/sync-version.sh`

Propagates version.txt into build.gradle and store metadata. Used by the release workflow and also by developers locally.

```bash
# Sync version.txt into all derived files
./scripts/sync-version.sh

# Check that derived files match version.txt (CI)
./scripts/sync-version.sh --check

# Print version for scripting
eval "$(./scripts/sync-version.sh --print)"
echo $version       # 0.1.0
echo $version_code  # 1000
```

### `scripts/test-release.sh`

Unit tests for the version sync logic. Runs in CI to catch format errors early.

```bash
./scripts/test-release.sh
```

### `scripts/fdroid-publish.sh`

Publishes a signed APK to the self-hosted F-Droid repository on the `gh-pages` branch. Invoked by the release workflow.

## Building Locally

### Debug Build

```bash
cd apps/web/android
./gradlew assembleDebug
```

The debug APK goes to `app/build/outputs/apk/debug/app-debug.apk`.

### Release Build (Unsigned)

```bash
cd apps/web/android
./gradlew assembleRelease
```

Output: `app/build/outputs/apk/release/app-release.apk`

### Release Build (Signed)

Requires a signing keystore. Create one or point to an existing one via `keystore.properties` (gitignored):

```properties
storeFile=path/to/release.keystore
storePassword=your_keystore_password
keyAlias=release_key_alias
keyPassword=your_key_password
```

Or pass via environment variables (how CI does it):

```bash
export ANYANG_CHEMISTRY_KEYSTORE_FILE=/path/to/release.keystore
export ANYANG_CHEMISTRY_KEYSTORE_PASSWORD=...
export ANYANG_CHEMISTRY_KEY_ALIAS=...
export ANYANG_CHEMISTRY_KEY_PASSWORD=...

cd apps/web/android
./gradlew assembleRelease bundleRelease
```

## GitHub Secrets Setup

The release workflow needs these secrets configured in your GitHub repository (Settings → Secrets and variables → Actions).

### Required for Signing

Set up at the **repository level** or in a **Prod environment** (recommended):

- `RELEASE_KEYSTORE_BASE64`: Your release keystore as base64
  ```bash
  base64 -w 0 release.keystore
  ```
- `RELEASE_KEYSTORE_PASSWORD`: Keystore password
- `RELEASE_KEY_ALIAS`: Key alias inside the keystore
- `RELEASE_KEY_PASSWORD`: Key password

### Optional: Release-Please Token

For better PR experience (so release PRs trigger CI):

- `RELEASE_PLEASE_TOKEN`: A GitHub PAT with `contents:write` and `pull-requests:write`

Without this, release-please falls back to GITHUB_TOKEN (which works but PRs won't trigger CI).

### Optional: Google Play Publishing

To auto-publish to Google Play's internal track:

- `PLAY_SERVICE_ACCOUNT_JSON`: Service account JSON from Google Play Console
- `ENABLE_PLAY_PUBLISH`: Repository variable set to `true`

See [Google Play Console docs](https://developer.android.com/studio/publish/app-signing#sign_release) for service account setup.

### Optional: F-Droid Publishing

To auto-publish to the self-hosted F-Droid repository:

- `ENABLE_FDROID_PUBLISH`: Repository variable set to `true`

The workflow uses the same signing key as the APK itself, so no additional secrets are needed.

## Store Metadata

App store listings (Google Play, F-Droid) read from `fastlane/metadata/android/`:

```
fastlane/metadata/android/
├── en-US/
│   ├── title.txt              # App name
│   ├── short_description.txt  # Brief summary (~80 chars)
│   ├── full_description.txt   # Full description (~4000 chars)
│   └── changelogs/            # Release notes by versionCode
│       ├── 1000.txt
│       ├── 1001.txt
│       └── ...
└── zh-CN/                      # Other locales
    └── ...
```

Release notes are auto-generated from `CHANGELOG.md` and placed in `changelogs/<versionCode>.txt` by `sync-version.sh`.

To add a new locale:

```bash
mkdir -p fastlane/metadata/android/<locale>/changelogs
# Add title.txt, short_description.txt, full_description.txt
```

## F-Droid Repository

The self-hosted F-Droid repository is built on every release and published to the `gh-pages` branch, served at:

```
https://508-dev.github.io/anyang-chemistry/fdroid/repo
```

Clients add it via the repo URL + fingerprint. The fingerprint is derived from the signing key, so rotating it breaks existing subscriptions (users must re-add the repo).

Configuration:

- `fdroid/config.yml`: F-Droid repo settings (signing material via env vars)
- `fdroid/metadata/dev.co508.anyangchemistry.yml`: App metadata for this repo

## Troubleshooting

### "could not set the version literals in build.gradle"

The version sync script couldn't find or update versionCode/versionName. Check that both literals are on their own lines in build.gradle:

```gradle
// ✓ Correct
versionCode 1000
versionName "0.1.0"

// ✗ Wrong
versionCode = 1000; versionName = "0.1.0"
```

### Play permanently rejects this versionCode

versionCode must strictly increase with every release. Once published, a versionCode cannot be reused. If you skip a version or release twice, the versionCode gap is permanent.

### Release notes are cut off

Release notes are truncated at 499 UTF-8 characters. If your CHANGELOG is long, only the first section (between the first and second `## ` header) is used.

### F-Droid index signing fails

Verify the keystore, passwords, and key alias all match:

```bash
keytool -list -keystore release.keystore -storepass yourpass -alias release_key_alias
```

The same keystore signs both the APK and the F-Droid index.
